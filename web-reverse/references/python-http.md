## HTTP 与解析库

库名不是白名单，不要求固定顺序逐个尝试。优先复用项目已有、实际可用的实现，并选择最少必要依赖。

| 需要 | 常见选择 | 关键点 |
| --- | --- | --- |
| 同步 HTML/JSON/API | requests、httpx、urllib3、标准库等 | 复用会话，设置真实支持的超时、重定向和重试策略 |
| HTTP/TLS 指纹兼容 | curl_cffi 等 | 依据实际差异选已支持的配置；不是 JS 执行器，不保证所有站点可用 |
| 已有异步实现或确有需求 | aiohttp、HTTPX/curl_cffi 异步接口等 | 少量分页验证通常串行即可，不新增并发调度框架 |
| HTML 的 XPath/结构提取 | lxml | 限定目标节点，处理编码和相对链接 |
| HTML 的搜索、CSS 与可读提取 | BeautifulSoup（beautifulsoup4，导入 bs4） | 显式选择解析器，避免换环境后自动改变解析树 |
| AES/RSA/摘要/签名 | Python 标准库、PyCryptodome、cryptography 等 | 优先 Python 等价还原，核对协议字节与参数，不默认引入 JS runtime |

`curl_cffi` 不内置浏览器/JS runtime，也不是 Requests 的完全等价替换，按实际版本核对接口与异常处理。[1][2]

## uv 依赖和运行方式

**默认在对应项目中安装依赖并运行普通 Python 脚本。** 先确定脚本所属的项目根目录，检查现有 `pyproject.toml`、`uv.lock`、Python 版本及 uv。脚本放在 `site-reproduction/<站点>/` 等子目录时，通常仍使用所在项目的依赖与环境；已有 uv workspace 时按实际成员归属处理，不误装到其他项目，也不为每个脚本另建子项目。

### 默认命令：uv add + uv run

进入对应项目根目录，用 `uv add` 安装代码真正使用的包，再用普通 `uv run python` 运行。以下仅以实际选用 Requests 与 PyCryptodome 为例，不固定 HTTP/算法库：

```bash
uv add requests pycryptodome
uv run python collector.py --page 1
```

脚本在子目录时，使用从项目根目录出发的实际相对路径。仅在该目录确实没有 Python 项目时先执行一次 `uv init --bare`；已有项目不重复初始化。保留已有依赖和必要版本约束，只增加缺少的直接依赖，不为追新升级无关包。[3]

`uv add` 会更新依赖声明、锁文件和项目环境；普通 `uv run` 会按项目配置检查并同步环境，必要时更新锁文件，无需机械地另执行 `uv lock` / `uv sync`。仅为恢复环境或编辑器准备时，可按需单独使用 `uv sync`。[3][4]

### 不把严格锁定或单脚本模式当默认

- 默认运行命令不加 `--locked`、`--frozen`、`--script`、`--no-project` 或临时 `--with` 依赖。依赖直接加入对应项目；`.py` 文件无需强制脚本解析参数。
- 项目 `uv.lock` 仍由 uv 正常维护。`--locked` 额外要求锁文件无需更新，否则报错；只有用户明确要求这种严格校验时才使用。去掉该参数不会让 uv 放弃项目锁文件，也不意味着每次升级全部依赖。[4]
- 不默认写 PEP 723 的 `# /// script` 内联依赖，不运行 `uv add --script` / `uv lock --script`，不生成 `collector.py.lock`。只有用户明确要求可独立分发的单脚本环境时才切换，不因代码只有一个文件就自行选择。

### 既有内联脚本迁回项目

若原脚本已经带有 `# /// script`，只删除 `--locked` / `--script` 并改用 `uv run collector.py`，仍会根据内联元数据使用独立环境并忽略项目依赖。按以下步骤迁移。[5]

1. 读取内联依赖、必要的 Python 版本约束和包源设置，将实际需要的声明合入对应项目；用 `uv add` 安装，保留合理约束，不盲目覆盖项目配置。
2. 移除该脚本的内联元数据，更新文件头、运行说明及入口命令；确认不再使用后，仅清理这个脚本已失效的 `.py.lock`，保留项目 `uv.lock` 和无关文件。
3. 从项目根目录以普通 `uv run python <脚本相对路径> ...` 实际运行，并在同一项目环境中另启 Python 进程复验。必要时检查 `sys.executable` 是否来自项目配置的环境。

### 依赖声明与环境

- 保留项目实际使用的声明与锁文件，不把整个环境的 freeze 当作直接依赖，不默认额外生成 requirements。锁文件是正常项目配套，不要求用户每次加锁定参数。
- 包名与导入名分开：`pycryptodome` 通常对应 `Crypto`；既有 `pycryptodomex` 项目对应 `Cryptodome`。`beautifulsoup4` 对应 `bs4`，不把 `cryptodome` 或 `bs4` 误写成默认依赖名。[6][7]
- `BeautifulSoup(content, "lxml")` 需要同时声明 `beautifulsoup4` 与 `lxml`；若选标准库 `html.parser` 就不必仅为该解析器增加 lxml。显式选择解析器。[7]
- 不用临时 pip 安装绕过项目依赖声明，也不默认改变全局 Python。只有现有项目明确采用 uv pip/requirements 管理方式时才按其约定适配。
- uv 或所需依赖不可用时，先尝试宿主允许的环境准备；无法完成则简明说明缺项。只报告实际执行过的命令和验证结果。

## 最小请求实现

通常一个 `collector.py` 即可，将客户端、请求构造、算法、HTTP、解析和分页分成清楚函数，不建设通用爬虫平台。

- 提供 `fetch_page(page)` / `fetch_batch(cursor=None)` 等入口；正确映射页码基数/offset，cursor 从真实响应取得。必要参数可传入，不写死只能取第一批。
- 每次请求及重试先完成节流等待，再用真实输入重算时间戳、nonce、签名/密文并发送。JSON/查询序列化、字段顺序和编码必须与计算使用的字节一致，不能签一种表示却发送另一种，也不能让等待使预先计算的签名过期。
- 时间戳、nonce、临时 token 和合法会话输入按实际协议更新。敏感值从受限输入/环境取得，不写入源码和结果；不向无关来源转发。
- Python 请求和解析必须独立于浏览器。临时 JS 对照不成为运行前提；仅在明确的最小 JS 例外成立时声明实际 runtime 依赖。
- 设置明确超时并统一请求节奏。HTTPX transport 的连接重试不包含所有读取异常/状态错误；关闭或计入库内自动重试，确保实际尝试不会绕过下节的等待和总次数上限。[8]
- 核对最终 URL、状态、MIME、业务标志、结构和目标值。异常 HTML、登录页、空壳和密文都不能冒充业务数据。保持 TLS 验证，不无差别重试授权错误。
- 代码头/短注释给出项目工作目录、必要的 `uv add` 与普通 `uv run python` 相对路径命令、端点和关键假设即可；不引用代理临时目录或技能内部绝对路径。

## 请求节奏、限流与退避

### 默认节奏

- 同站点主动请求默认串行。未取得明确频率规则时，基础间隔取 3 秒，并附加 0–2 秒小幅随机延迟；在上一次请求完成或失败后计时，再发送下一次。已有平台配额或冷却要求更慢时以其为准。这是可调工程默认，不能承诺不会触发限制。
- 用一个简单的等待/请求入口统一初始化、分页、详情、分析用脚本下载、手工重放和重试。基础间隔与抖动可配置，默认运行命令无需增加参数；不默认建立并发调度、共享数据库或断点存储层。
- 使用单调时钟跟踪间隔/下一次允许发送的时刻；等待结束后再生成本次请求的时间戳、nonce 和签名。异步实现使用异步等待，不通过多个任务同时发送规避节奏。
- 同一平台或凭据已受限时，冷却适用于本轮相关请求，不跳到下一页继续打接口；换会话、客户端或新 Python 进程复验也不能重置冷却。分析和验证依次进行，启动下一进程前安排剩余等待即可。

### 限流信号与等待

429 是标准频率限制信号；响应正文中的明确频控信息也应触发暂停。503 表示服务暂不可用，需结合响应决定是否有限重试。不要把所有 403、超时或空数据一律诊断为封禁；先暂停自动重试并检查已有证据。[9][10]

- `Retry-After` 支持非负整数秒数和 HTTP-date。秒数从收到响应后起算；日期按 UTC 解析并转换为剩余等待，可使用 `email.utils.parsedate_to_datetime`。过期日期不抵消本地间隔；格式无效时回到本地退避。[10]
- 每次重试等待取正常请求间隔、本地退避和有效服务端等待中的较大值；额外抖动只能延长等待，不得提前。服务端值很大时不得用本地最大等待值强行截短；本轮无法合理等待则停止在线请求，先完成仍可推进的离线分析，再简短说明验证受阻及恢复条件。
- 对允许重试的短暂故障使用递增退避；429/503 无有效等待信息时，默认可从 30 秒起，随后 60 秒。所有额外尝试仍共用单个逻辑请求最多 2 次的预算，不套多层循环、不在 HTTP 库内部再增加隐式次数。连续限流或明确封控可提前停止在线请求，无需耗尽次数；离线分析按主文档继续或收束。
- 401/403 先核对认证头、正文、跳转、正常游客初始化与会话条件；只有已有证据支持具体修正时才继续低频验证，不单凭状态码判定必须人工登录。明确需要登录/权限或人工验证且条件缺失时直接结束；明确封禁、持续限流或频控未解除时停止在线请求，不通过持续重放或更换工具绕过冷却。
- 自动重发预算与逆向分析深度分开：达到重试上限后不能继续原样请求，但可离线分析、定位差异并评估其他有证据的路径。新发现不重置已有冷却或明确封控；仍可推进的技术分析不因“最多重试 2 次”结束。

### 有限验证

实际小样本请求应观察默认间隔生效；需要检查退避时，用本地模拟响应/可控时钟覆盖秒数、HTTP-date、缺失/无效头和重试上限，按具体风险选择最少检查。不要故意向目标站点快速请求来制造 429，也不要为了证明不会封控而做压力测试。少量成功不能保证源站以后不变更限额。

## HTML 保存为 JSON 或 Markdown

按目标内容直接选择，不让用户为默认格式补填表单：

| 内容 | 默认结果 |
| --- | --- |
| API/内嵌/解密后的业务 JSON | JSON，保留目标结构、真实类型和数值语义 |
| HTML 列表、表格或明确字段 | 提取后的 JSON，字段命名清楚，缺失值如实表达 |
| HTML 文章、说明文、以阅读为主的内容 | Markdown，保留有意义的标题层级、段落、列表、链接及适用的表格/代码块 |

用 lxml/bs4 等定位用户所需部分，排除不相关导航和脚本，基于实际最终 URL 解析相对链接。正文不能简单压成一行；Markdown 也不能只是原始 HTML 改扩展名。使用适用的转换方法并回读检查；确需额外转换库时通过 uv 声明真实依赖。

默认只保存一种少量结果。不要额外留原始 HTML、TXT、多份中间 JSON、JSONL、CSV/Excel 或报告/旁证。用户明确指定格式时遵从其要求。代码、依赖声明和实际必要的锁文件继续保留。

## 分页验证与失败出口

1. 用保存的 Python 入口取得真实目标值，与少量页面/响应样本核对。
2. 通常验证 2–3 个不同页/连续批次。允许站点本身部分重叠，但不能把仅时间戳变化的同一页当作翻页成功；动态计算随分页输入更新。
3. 遵守本轮剩余间隔/冷却后，在同一项目根目录用普通 `uv run python` 另启进程复验至少一个请求，确保项目依赖、初始化与动态输入可重建，不依赖打开的浏览器。
4. 回读 JSON 或 Markdown，确认目标字段/内容完整、中文和链接正确，不把文件存在当作采集成功。

关键请求或分页尚未复现时，继续检查初始化、实际发送字节、签名覆盖的分页字段、游标和 token 生命周期；停止统一遵循主文档第 6 节，不能以“分页失败”本身作为终止理由。满足停止条件后，用 2–4 句说明未完成/部分验证、最深已验证位置、具体原因和限制。不调用浏览器批量提取 DOM/响应，不用 Playwright request API 兜底，不输出替代采集方案或长日志。单页站点无下一页可验证时如实说明，不虚构分页。
